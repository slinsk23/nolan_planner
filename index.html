Practice Planner

Press + Session on a day to book a client. Sessions that overlap each other or a Google Calendar event are marked Conflict; sessions closer together than your buffer are marked Tight. Click a line to add a task and press Enter; start it with ! to make it a deadline. Drag sessions or tasks to another day. Client names and notes stay in this browser and are never sent to Google; Google Calendar only gets the label you choose in Settings. Use Settings → Export backup regularly.

      Google connection

      Paste the OAuth Client ID from your Google Cloud project (setup steps below), then connect. The planner reads your main Google Calendar to check for conflicts, and puts sessions and tasks on a separate calendar called “Practice,” which it creates for you.

      Send to the “Practice” calendar
      Session label in Google

      Only the label, time and format (in person or telehealth) go to Google. Names, notes and session status stay here. A personal Google account isn’t covered by a HIPAA business associate agreement, so keep identifying details out of Google Calendar.

      Backup

      Everything is saved in this browser only. The backup file contains client names and notes, so store it somewhere secure.

      One-time Google setup (about 10 minutes)
      1. Go to console.cloud.google.com and create a project (any name, e.g. "Practice Planner").
      2. Open APIs & Services → Library and enable Google Calendar API.
      3. Open Google Auth Platform (or OAuth consent screen), choose External, fill in the app name and your email. Under Audience → Test users, add your own Gmail address.
      4. Open Clients (or Credentials) → Create client → type Web application. Under Authorized JavaScript origins, add the address this page runs from:
      5. Copy the Client ID, paste it above, and press Connect Google. Google will warn that the app isn't verified; choose Continue, since it's your own app, and allow access to your calendars.

      Google sign-in doesn't work when the file is opened by double-clicking (a file:// address). Host it on GitHub Pages or run a local server.
